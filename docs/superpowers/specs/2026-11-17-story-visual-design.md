# Hình kể chuyện

The user's implementation request and subsequent correction authorize replacing the two former visual/text concepts with one new concept: **Hình kể chuyện**, `story_visual`.

One entity, one scene owner, one SVG per visible state, one set of voice-anchored events. An illustration, outlined lettering, or their combination are expressions of this same concept. Optional `lettering` describes words/styles on its states; it is not another role, entity kind or coverage layer. There is no integration flag and no mutual-exclusion rule between illustration and words inside the image. Actors, physical props, environmental accents and runtime captions keep their existing roles.

Phase 1 supplies `story_visuals` and an explicit `story_visual_decision`. Directions state the concrete visible action, viewer reading and contribution to narration. Phase 2 implements that meaning as assets, states, layout and optional lettering. Current prompts, manifests, exports and validators use only the new vocabulary. Internal Job@5 `story_object` transport remains unchanged, so the renderer needs no additional semantic layer.

The chosen approach reuses the existing SVG/state pipeline and lettering outlines. Keeping two entities or a compatibility flag would preserve the rejected distinction; a separate renderer would add an unnecessary runtime. Older immutable capsules remain preserved as evidence rather than silently acquiring new approvals.
