# Context budget for Job@5 (v2.4.33)

## Objective
Keep **all** manifest validators, native compilers, approval proofs, and ZIP checks. Reduce tokens spent on unrelated guidance and repeated serialized state. No model-side shortcuts count as a capability receipt.

## Step-scoped loading
Use `node orchestration/plan-step-context.mjs 02-visual-production visual_compile` (or `assets`, `publish_prep`; similarly for all Phase 01/03 steps) to select mandatory reference paths and input context. Conditional `flag:` capabilities are included only when active, but their validators must run when applicable. Do not load every reference in 26K-character Phase 02 manifest into the agent's active working text. Read manifest structure programmatically, and fetch actual guidance for the current step just-in-time.

## Minimal continuation handoff
Carry only: run_id; current_phase and step; immutable approved narration reference+SHA256; source paths and SHAs for authored decisions; approval receipt reference; real validator receipt paths+exit codes; unresolved blockers and next required action. The persisted pipeline-state.json remains authoritative; a compact handoff is not a substitute or a new state format.

## Ownership
Agent authors semantic decisions (story-object metaphor and beats, environment selection, cast intent, design rationale, palette). Native compilers derive SVG, geometric transforms, manifests and hashes. Runner measures audio frame timing, real visual bounds, caption fit, raster preview and final MP4. Never ask the agent to transcribe a compiler output or repeat generated JSON simply to communicate between steps.

## Safety
The context planner is **read-only/advisory**: it MUST NOT skip a manifest-required reference, validator, output, approval, or post-ZIP verification. An unknown step/phase or missing source blocks instead of guessing. Read the applicable full contract when editing its semantics.

## Review findings and guardrails (v2.4.34)
The read-only capsule is a **pointer and digest**, not an extra state machine, source or receipt. It must not include large asset arrays, full narration or authoring JSON. Build it from the original persisted state each time; never use it to repair missing state or certify a phase. Conditional capabilities fail closed when a flag value is absent, malformed or a condition is unsupported. Keep validation and user approval flows unchanged.

Use `node orchestration/context-capsule.mjs <workspace>` only for compact handoff, then `node orchestration/plan-step-context.mjs <phase> <step> --flags <pipeline-state.json>` for next step. This is a context-only optimization; no timings/pixel geometry/creative decisions are generated by these tools.

## Single-source scene decisions (v2.4.35)
Do not restate the whole production scene, event list, cast design and depth decisions in each prompt. When working on a single scene, run `node orchestration/derive-scene-context.mjs <workspace> <scene_id>` and read the bounded scene index with exact file references and source SHA-256. Open the underlying authoring plan **only** for decisions being edited or verified. This derived index never becomes a source of creative choices, state, receipts, animation approval, or validation results. Unknown scene, orphan/duplicate plan IDs or missing production block context. Existing validators and native compilers run unchanged.

## Intentional reuse versus creative repetition (v2.4.36)
Run `node orchestration/audit-creative-reuse.mjs <workspace>` after Visual Compile and before human Visual Review. It reports repeated frame/mechanic/palette/environment, identical three-scene Story Object choreography and primary-story master reuse across different semantic needs. **No quotas and no forced variants**: retaining a character, shirt color, prop or background through a continuous setting is good reuse. A creative flag requires explicit editorial consideration or a justified continuity note, not automatic SVG generation. Generated report is NOT a validator receipt, authoring source or PASS evidence. On rerun with unchanged input, reuse the report; invalidate only when its source files change.

## Bounded Phase2 guidance
Persist selected_asset_ids, meme_selected and environment_mode in the current context request. plan-step-context loads core plus selected extension references and hashes exact bytes; missing reference blocks. For archive_frame, retain exact wall/floor frame, use separate semantic props, and do not add automatic architecture. Do not invoke the depth wrapper unless a depth composition plan is explicitly selected. Capability/validator/approval requirements remain intact; applicability receipts refer to the bounded selection index.
