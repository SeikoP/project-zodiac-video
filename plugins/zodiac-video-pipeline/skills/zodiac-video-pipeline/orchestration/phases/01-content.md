# Phase 1 — Content

Finish Evidence → Concept → Narration, then enter `IN_REVIEW` for CONTENT REVIEW.

1. **Evidence** — run fresh discovery/verification, write `evidence-ledger.json` + `evidence-summary.md`, then run `validate-evidence-contract.mjs <workspace>`. Evidence needs at least two independent source identities and their supported interpretation.
2. **Concept + Story Engine (Zodiac-first)** — for new 2.4.13+ runs, generate three distinct `concept-candidates.json` premises and choose a winner using `references/content-quality-engine.md`. Link its ID in `narrative-plan.json.selected_concept_id`. Reject a weak story before polishing hook. Then decide `flags.viral_support_needed` from the current content task, before entering the concept step. Read `references/viral-routing-policy.md`. Invoke the installed Viral Analysis guidance **only if** that flag is true, recording a real `skill_read`/`plugin_result` receipt and an application summary. When false, do not invoke it and do not fabricate its receipt. A lean *internal editorial-mechanics* `viral-analysis.json` still exists for the unchanged Content Engine v2 downstream contract; it is **not** proof of an external Viral plugin invocation. Compile reference mechanics, Story Spine and writer brief. Run `validate-content-contract.mjs <workspace>` with exact lineage and resolvable evidence refs.
3. **Narration** — apply `TONE_RHYTHM_DEFAULT` from `references/character-viral-performance.md` and `references/narration-rhythm.md`: vary delivery/energy/emotion/pace/emphasis by semantic beat, with no required emotional sequence; keep evidence boundaries. Fresh >=2.4.47 authors Narrative Plan 2.0 and binds actual voice anchors after the draft. From the minimized writer brief + minimal evidence only. After writing, audit the full approved Story Spine against **actual narrator decisions, response/state changes and beat-level semantic deltas** using `references/story-spine-performance.md`. Emit `story-spine-performance.json` with excerpt-grounded assessment for all four spine anchors and every beat, then run `validate-story-spine-performance.mjs` with actual execution receipt. Any missing or only-rephrased beat is `REVIEW`, never auto-PASS. Then run `validate-narrative.mjs` and `validate-narrative-qc.mjs`. For new 2.4.13+ content, run separate independent editorial challenge and create `story-quality-review.json`; run `validate-story-quality-review.mjs` through receipt wrapper. Its contract PASS never proves inherent creative quality; unresolved weaknesses must be REVIEW and reworked at the Concept step. Do not send the full plan to the writer; post-write QC owns this check.

After all steps pass set phase `IN_REVIEW`. Content `PASS` and Phase 02 require explicit user approval with actual `user_message` receipt. Do not re-open previously approved parts unless their source or semantics changed. The conditional skill flag is about *advice*, not permission to skip gates or overwrite reviewed content.

No assets, rendering, packaging or ZIP creation belong here.


## Mandatory identity-first preflight (new 2.4.15+)
Before writing candidates or a school-life setting, read `references/zodiac-identity-first.md`, identify sign mechanism and three distinct facets, and run the sign replacement thought experiment. A candidate that remains coherent after changing the sign must be rejected regardless of hook or storytelling score. The independent review must assess `zodiac_identity_review` (sign swap, scene dominance, moral arc) in addition to the six existing content quality criteria. Run the deterministic contract validator; failures return to Concept. User approval remains required. A previous Phase 01 user review does not auto-approve rewritten content.
Fresh >=2.4.48 uses native evidence/writer brief compilation, source lineage and plugin-use decisions; see phase01-briefing.md. Video Lab does not replace this phase. Use draft scope for writing and review scope for actual narration/QC. Commit genuine step receipts with commit-phase01-step.mjs before progressing; no automatic Content Review approval.

After an explicit user Content Review, record the existing user_message proof via buildSourceBoundReviewReceipt in approval-source-hashes.mjs; commit source_hashes with that receipt. This helper binds evidence and cannot replace user approval. New visual-intent runs require this binding. Existing legacy approvals are retained as legacy, never silently migrated. Phase3 commits native owned substages, actual execution receipts and ZIP identity atomically after export; recovery commits state only and keeps runner media pending.
