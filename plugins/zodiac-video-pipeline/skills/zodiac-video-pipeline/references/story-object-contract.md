# Narrative Visual — canonical fresh authoring contract

Fresh authoring uses exactly one narrative concept: `narrative_visual`.
It visualizes thoughts, emotion, symbolic meaning, comparison and visual
transformations independently from background and physical props.

A narrative visual can anchor to an actor, group or the canvas itself; an
above-head or near-actor placement requires no held-by, floor or surface
contact. Its position is authored and checked for spatial/caption safety.
One readable visual state is sufficient for a simple representation.
For a narrative progression, author meaningful state changes, preserve
conceptual identity and bind transitions to genuine narration anchors.
Setup/friction/payoff applies only when the story actually contains that arc.
Effects are optional emphasis, never compulsory decoration.

Keep the same actor, prop and narrative-visual identities across scene beats.
Do not create duplicate symbolic entities for the same narrative function.
Story visuals never replace the canvas background.

## Compatibility boundary

Existing `story_object`, `story_symbol` and `visual_metaphor` remain
legacy inputs. They are normalized to the existing `story_object` Job@5
transport role at export. No schema hash change or renaming of approved
serialized assets is permitted. Older Story Object plan @2 shape and its
three-beat validation remain readable for historical packages only.

Review gates remain separate: structural validation, human creative review and
runtime QA. A valid state change cannot substitute for an actual readable
rendered frame.
